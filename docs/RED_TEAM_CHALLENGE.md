# PADAM Agentic Shield — Open Red Team Challenge & Independent Verification

> **Honesty first:** The built-in `padam shield benchmark` (1,200 attack vectors across 40 categories + 250 benign developer tasks across 15 categories) is a **built-in deterministic self-check**, **NOT** an independent third-party security audit.
>
> Numbers generated by a vendor's own test suite should never be taken on faith. We invite security researchers, Web3 engineers, and AI developers to **inspect every vector, run the shield against your own unseen attacks and real-world benign prompts, and try to break it**.

---

## 1. Verify or Break in 60 Seconds (Zero-Telemetry, 100% Local)

Everything runs locally on your machine with **zero network calls** and **zero telemetry**.

### Step 1 — Audit the entire built-in corpus yourself
Export all 1,200 built-in attack vectors and 250 benign prompts to plain JSONL with SHA-256 checksums so you can inspect every single sample:

```bash
padam shield benchmark --export-corpus ./padam_audit_corpus
```

This creates:
- `./padam_audit_corpus/attacks_1200.jsonl`
- `./padam_audit_corpus/benign_250.jsonl`
- `./padam_audit_corpus/MANIFEST.json` (SHA-256 hashes of both files)

### Step 2 — Run against YOUR OWN unseen attacks & real prompts
Create two JSONL files with prompts the shield has **never seen before**:

- `my_attacks.jsonl` — each line: `{"id": "A1", "kind": "prompt", "text": "..."}` (supported `kind`: `prompt`, `sql`, `nosql`, `graphql`, `diff`, `url`, `os`, `rules`, `dom`, `iac`, `xml`, `yaml`, `voice`, `test_diff`, `stego`, `inbound`).
- `my_benign.jsonl` — real everyday developer prompts, diffs, SQL queries, emails, or HTML pages from your workflow to stress-test **False Positive Rate (FPR)**.

Run the evaluation and generate a reproducible Markdown receipt:

```bash
padam shield benchmark \
  --custom-attacks my_attacks.jsonl \
  --custom-benign my_benign.jsonl \
  --markdown-report verification_receipt.md
```

Or run the built-in self-check on your own OS/Python environment and save a receipt:

```bash
padam shield benchmark --markdown-report self_check_receipt.md
```

### Step 3 — Publish your findings (Verified OR Broken)
Open a GitHub Issue or Discussion titled `[Red Team Challenge] Independent Verification Receipt` and paste `verification_receipt.md`.

- **If it holds:** Your independent verification receipt is linked in the Verification Registry below.
- **If you break it (bypass or false positive):** Every reproducible bypass or false positive is logged transparently in the **Honest Corrections Ledger**, patched in the codebase with a permanent regression test, and credited to you.

## 2. Scope & What We Explicitly Want You to Attack

1. **False Positive Rate (FPR) on real developer traffic** — especially non-English prompts (RU/ES/ZH/DE/JA), complex SQL/GraphQL queries, legitimate security documentation, and long multi-turn conversations (`crescendo_guard`).
2. **Unseen Prompt Injection & Memory/Rules Backdoors** — novel phrasings outside our built-in corpus targeting `.cursorrules`, `CLAUDE.md`, `AGENTS.md`, `SKILL.md`, and RAG documents.
3. **Web3 & Payment Firewall (`web3_abi`, outbound gate)** — EVM calldata / Permit2 / SetApprovalForAll / Solana SPL `SetAuthority` / address-poisoning bypasses.
4. **Protocol & Sandbox Boundaries** — MCP STDIO/HTTP proxy bypasses, Cloud IMDS SSRF encodings, Zip-Slip / XXE / YAML RCE edge cases, and Stego DLP evasions.
5. **Cryptographic & SQLite Integrity** — attempts to tamper with `tamper_seal`, `attestation` hash chains, `approval_binding` anti-TOCTOU receipts, or `capability_tokens` attenuation limits.
