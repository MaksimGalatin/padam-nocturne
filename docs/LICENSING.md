## 1. Почему выбрана именно связка AGPL-3.0-only + Apache-2.0 + Commercial

1. **Защита от паразитарного клонирования облачными гигантами (`AGPL-3.0-only` на `padam/`):**
   Лицензии уровня `MIT` или `BSD` позволяют любой крупной компании забрать ваш код защиты памяти, поднять платный облачный сервис и не отдать обратно ни строчки и ни доллара. Лицензия `AGPL-3.0-only` (уже закреплённая в [`pyproject.toml`](../pyproject.toml) и [`LICENSE`](../LICENSE)) обязывает каждого, кто делает закрытый сетевой сервис поверх `padam/`, либо открыть код всем пользователям, либо приобрести **Коммерческую лицензию у CODE Eternal LLC**.
2. **Нулевое юридическое трение для CI/CD (`Apache-2.0` для `.github/actions/padam-agentic-shield/`):**
   Большинство банков и корпораций принципиально не пускают код с лицензиями GPL/AGPL в сборочные конвейеры своих проприетарных репозиториев, но безоговорочно разрешают `Apache-2.0`. Вынесение GitHub Action и CI-шаблонов под `Apache-2.0` (с явной патентной оговоркой) снимает любой стопор в отделе закупок: клиент ставит наш CI-чек за 2 минуты бесплатно, видит реальные дыры SRI/CSP и через 1–2 недели приходит за коммерческим корпоративным пакетом (Shield Runtime + SIEM + SLA).
3. **Предсказуемая монетизация (`Commercial License`):**
   Крупные компании (финтех, банки, B2B SaaS, маркетплейсы) никогда не покупают «просто так пожертвование» — они покупают коммерческую лицензию с договором MSA, DPA, счётом от американского юридического лица (`CODE Eternal LLC`, New Mexico, Entity ID `0008138873`) и SLA.
