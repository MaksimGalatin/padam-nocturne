Ciclo de sueño NOCTURNE y capa eterna L3

Cómo cuatro limitadores evitan que los desastres monopolicen la consolidación, cómo funcionan los dos relojes y cómo borrar en cadenas inmutables.

Cuatro limitadores contra el sobreajuste a catástrofes

En un búfer sintético (1 000 episodios normales + 612 catastróficos), el muestreo priorizado simple da a las catástrofes el 90.7 % (~181 de 200). Con los cuatro limitadores queda acotado en 50 de 200 (0.25):

  • Suelo de prioridad P_FLOOR = 0.01 * median(p) para no olvidar la rutina.
  • Tope para episodios extremos K_MAX = 0.25 (perfiles: default 0.25, ops 0.40, creative 0.10).
  • Decaimiento tras reproducción gamma_replay = 0.85.
  • Pesos de importancia w_i = (1 / (N * P(i)))^beta y muestreo estratificado.

Siete tipos de registro y dos relojes

El decaimiento Δt se calcula desde last_confirmed_at, nunca desde last_seen_at, evitando que un error recuperado con frecuencia permanezca fresco.

Anclaje L3: Arweave + Solana + Bitcoin OTS

  1. Cifrado individual por registro: AES-256-GCM (nonce(12) || ciphertext).
  2. Árbol de Merkle: hoja de registro SHA256(0x00 || bytes), hoja de olvido SHA256(0x02 || 'AIFA-FORGET|id|time'), nodo SHA256(0x01 || L || R).
  3. Carga a Arweave (Turbo gratuito bajo 100 KiB), raíz en Solana Memo (PADAM-NOCTURNE v1 ...) y sello OpenTimestamps en Bitcoin.
  4. Olvido criptográfico (padam forget): limpieza local (secure_delete + VACUUM), destrucción de la clave y recibo JSON/HTML.
python -m padam sleep
python -m padam l3 --dry-run
python -m padam l3 --network devnet
python -m padam l3-verify
python -m padam forget <record_id> --with-derived --receipt deletion_proof.html
