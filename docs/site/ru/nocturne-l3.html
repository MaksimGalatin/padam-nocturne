Протокол сна NOCTURNE и вечный слой L3

Почему обычная приоритетная память превращается в «кошмар из катастроф», как устроены два независимых часа и как стереть запись в неизменяемом блокчейне.

4 ограничителя NOCTURNE против перекоса в катастрофы

На синтетическом буфере (1 000 обычных + 612 катастрофических эпизодов) обычный Prioritized Experience Replay отдаёт катастрофам 90.7 % выборки (~181 из 200). Четыре ограничителя снижают долю ровно до 50 из 200 (0.25):

  • Пол приоритета P_FLOOR = 0.01 * median(p) — рутина никогда не замирает до нуля.
  • Потолок доли острых эпизодов K_MAX = 0.25 (настраивается профилями ops=0.40 / creative=0.10).
  • Затухание приоритета после проигрывания gamma_replay = 0.85 — один и тот же кризис не крутится вечно.
  • Коррекция смещения важности w_i = (1 / (N * P(i)))^beta — математически честная оценка при обучении и стратификация остатка.

Вечный слой L3: Arweave + Solana + Bitcoin OpenTimestamps

  1. Каждая запись шифруется собственным ключом AES-256-GCM (nonce(12) || ciphertext).
  2. Дерево Меркла: лист записи SHA256(0x00 || bytes), лист забывания SHA256(0x02 || 'AIFA-FORGET|id|time'), узел SHA256(0x01 || L || R).
  3. Пакет шифротекстов загружается в Arweave (бесплатно до 100 КиБ через Turbo), корень Меркла — в Solana Memo: PADAM-NOCTURNE v1 root=... n=... ar=... d=..., а слепок хеша штампуется в Bitcoin через OpenTimestamps.
  4. Крипто-забвение (padam forget): локальная копия стирается с secure_delete + VACUUM, ключ записи уничтожается навсегда, шифротекст на Arweave становится белым шумом, а владелец получает квитанцию (JSON/HTML).
python -m padam sleep
python -m padam l3 --dry-run
python -m padam l3 --network devnet
python -m padam l3-verify
python -m padam forget <record_id> --with-derived --receipt deletion_proof.html
