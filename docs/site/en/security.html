Security Model, Fencing & Red Team Measurements

Memory read back into prompts is both an injection and a leakage vector. Structural boundaries protect even when word filters are bypassed.

Five structural defences

1. Pre-disk secret masking

20+ API key patterns, Solana id.json / base58 / 12- and 24-word recovery phrases (keeping public addresses intact) and Luhn cards become [REDACTED:...] before reaching SQLite.

2. Injection hold queue & PADAM_STRICT=1

13-language filter (with homoglyph & encoding decoding) + forced origin='external' for Chrome extensions. Under PADAM_STRICT=1 every agent write waits for owner review.

3. 128-bit random Data Fence

All search, timeline and profile replies are wrapped in tags with a fresh 32-hex nonce per call so stored content cannot close the fence. Only padam_export stays raw JSON.

4. Owner-signed profile

Identity and preference records carry an HMAC owner signature. padam_profile and GET /profile ignore tampered/unsigned records.

5. Per-record keys & Shamir legacy

protect-keys wraps per-record keys with scrypt + AES-256-GCM + VACUUM. legacy split/combine splits the passphrase into k-of-n Shamir shares; panic destroys every key.
